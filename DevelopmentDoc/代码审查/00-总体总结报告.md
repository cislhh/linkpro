## 关键问题分类

### 1. 数据获取架构问题 (🔴 严重)

**问题描述**:
- 多个组件在客户端重复获取相同数据
- 没有统一的数据管理策略
- Dashboard 加载后，每个子页面都重新获取数据

**影响**:
- 增加 TTI (Time to Interactive)
- 浪费网络请求
- 用户体验差

**涉及的文件**:
- `src/components/features/preview/layout-preview.tsx`
- `src/components/features/modules/module-edit-dialog.tsx`
- `src/components/features/profile/profile-form.tsx`
- `src/components/features/link-editor/link-form.tsx`

**建议解决方案**:

```
┌─────────────────────────────────────────────────────┐
│        当前架构 (有问题)                              │
├─────────────────────────────────────────────────────┤
│ Dashboard Layout                                     │
│     ↓                                                │
│ Dashboard Page (/dashboard)                         │
│     ↓                                                │
│ Preview Component → useEffect → getModules()        │
│     ↓                                                │
│ Profile Component → useEffect → getUserProfile()    │
│     ↓                                                │
│ Links Component → useEffect → getUserLinks()        │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│        建议架构                                       │
├─────────────────────────────────────────────────────┤
│ Dashboard Layout (Server Component)                 │
│     ↓                                                │
│ 并行获取所有数据:                                     │
│   - getModules()                                     │
│   - getUserLinks()                                   │
│   - getUserProfile()                                 │
│     ↓                                                │
│ DashboardDataProvider (传递初始数据)                 │
│     ↓                                                │
│ 各组件从 context/store 读取数据                       │
└─────────────────────────────────────────────────────┘
```

### 3. 无限循环风险 (🔴 严重 - 已修复 1 处)

**历史问题** (已修复):

**潜在风险**:
- `module-edit-dialog.tsx` 第 91, 118 行 - ESLint 禁用警告
- 多处 useEffect 依赖可能不完整

### 4. Server Actions 混用 (🟡 中等)

**问题**:
- `layout-store.ts` 中在 `setModules` 里调用 Server Action
- 违反了 Server Components 应处理数据获取的原则

**建议**:
```typescript
// ❌ 当前
setModules: async (modules) => {
  const layouts = await getDeviceLayouts();
  // ...
}

// ✅ 建议
setModules: (modules, layouts) => {
  set({ modules, layout: layouts ?? generateDefaultLayout(modules) });
}
```

### 5. 原始 SQL 使用 (🔴 严重)

**问题**:
- `src/app/u/[username]/page.tsx` 使用 `$queryRaw`

**建议**:
```typescript
// ❌ 当前
const users = await prisma.$queryRaw<Array<{...}>>`
  SELECT id, username, ... FROM "User" WHERE username = ${username}
`;

// ✅ 建议
const user = await prisma.user.findUnique({
  where: { username },
  select: { /* ... */ },
});
```

## 优先级修复计划

### 第一阶段 (🔴 高优先级 - 1-2 周)

1. **统一数据获取架构**
   - 创建 `DashboardDataProvider`
   - 在 Dashboard Layout (Server Component) 中获取初始数据
   - 移除各组件中的 useEffect 数据获取

2. **移除原始 SQL 查询**
   - 替换 `$queryRaw` 为 Prisma 查询
   - 保持类型安全

3. **移除调试日志**
   - 移除生产环境中的 console.log

### 第二阶段 (🟡 中优先级 - 2-3 周)

1. **拆分大型组件**
   - 重构 `module-edit-dialog.tsx`
   - 重构 `profile-form.tsx`

2. **优化 Server Actions**
   - 移除 Store 中的 Server Actions 调用
   - 添加 React.cache() 去重

3. **实现乐观更新**
   - 在表单提交中使用乐观更新
   - 减少等待时间

### 第三阶段 (🟢 低优先级 - 持续改进)

1. **性能优化**
   - 添加 memo 优化组件
   - 使用 dynamic import 减少初始 bundle

2. **类型安全改进**
   - 移除 `any` 类型
   - 创建完整的类型定义

3. **添加缓存策略**
   - 使用 Next.js revalidate
   - 实现 SWR 或 React Query

## 总结

LinkPro 项目整体代码质量良好，但存在以下关键问题需要解决：

1. **数据获取架构不统一** - 最严重的问题，需要优先解决
2. **大型组件需要拆分** - 提高可维护性
3. **原始 SQL 使用** - 安全风险
4. **缺少请求去重** - 性能问题

通过按照上述优先级计划进行重构，可以显著提升代码质量和用户体验。
