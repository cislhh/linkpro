## 问题列表

### 1. Auth Guard 中的逻辑问题

**文件**: `src/components/providers/auth-guard.tsx`
**行号**: 48-70

**问题描述**:
非"记住我"会话的浏览器关闭检测逻辑不完整。当前实现过于宽松，无法正确检测浏览器关闭并清除会话。

**当前代码**:
```typescript
if (!isActiveSession) {
    // No active session marker in sessionStorage
    // This is either a fresh login or browser was reopened
    // For now, we'll be lenient and just set the marker
    sessionStorage.setItem(sessionKey, "true");
}
```

**问题分析**:
- 注释中提到需要区分"新登录"和"浏览器重新打开"，但实际实现总是设置为允许
- 没有实现真正的"关闭浏览器即登出"功能
- sessionStorage 在浏览器关闭时应该自动清除，但代码逻辑没有利用这个特性

**修改建议**:
1. 登录时设置 sessionStorage 标记
2. 在 AuthGuard 中检查标记是否存在
3. 如果标记不存在且 loginExpiry 为 null（非记住我），则登出用户

**修改思路**:
```typescript
if (!isActiveSession && !loginExpiry) {
    // sessionStorage 标记不存在，且没有登录过期时间
    // 说明浏览器被关闭后重新打开，应该登出
    clearAuth();
    signOut({ callbackUrl: "/login" });
    return;
}
// 新登录情况，设置标记
if (!isActiveSession) {
    sessionStorage.setItem(sessionKey, "true");
}
```

### 2. NextAuth 类型定义不一致

**文件**: `src/types/next-auth.d.ts`
**行号**: 4-31

**问题描述**:
类型定义中缺少 `image` 字段，但在 `lib/auth.ts` 中使用了该字段。

**当前代码**:
```typescript
// types/next-auth.d.ts
interface Session {
  user: {
    id: string;
    username: string;
    phone?: string | null;
    contact?: string | null;
    bio?: string | null;
  } & DefaultSession["user"];
}

// lib/auth.ts 第58行
return {
  // ...
  image: user.avatarUrl,  // avatarUrl 被映射为 image
};
```

**问题分析**:
- NextAuth 默认的 Session.user 包含 `image` 字段
- 当前类型定义中没有显式声明 `image`，导致类型不匹配

**修改建议**:
在 `next-auth.d.ts` 中添加 `image` 字段声明，或使用 `@ts-expect-error` 注释

**修改思路**:
```typescript
interface Session {
  user: {
    id: string;
    username: string;
    phone?: string | null;
    contact?: string | null;
    bio?: string | null;
    image?: string | null;  // 添加此字段
  } & DefaultSession["user"];
}
```

### 3. Auth Store 中的 `isSessionValid` 方法逻辑问题

**文件**: `src/stores/auth-store.ts`
**行号**: 67-86

**问题描述**:
当 `rememberMe` 为 false 时，`isSessionValid` 方法返回 false，但这个方法本身不会被调用（因为非记住我会话由 sessionStorage 处理）。

**当前代码**:
```typescript
isSessionValid: () => {
    const state = get();

    // If not using remember me, session validity is handled elsewhere
    if (!state.rememberMe) {
        return false;
    }
    // ...
}
```

**问题分析**:
- 这个方法的返回值在非记住我情况下是误导性的
- 注释说"handled elsewhere"，但返回 false 会让调用者误判会话状态

**修改建议**:
方法应该抛出错误或返回 undefined，表明不应在非记住我情况下调用此方法

**修改思路**:
```typescript
isSessionValid: () => {
    const state = get();

    if (!state.rememberMe) {
        // 此方法仅适用于"记住我"会话
        console.warn("isSessionValid should not be called when rememberMe is false");
        return false;
    }
    // ... 其余逻辑
}
```

### 4. 路由保护中的 callbackUrl 丢失

**文件**: `src/app/(dashboard)/dashboard/layout.tsx`
**行号**: 15-22

**问题描述**:
路由保护时硬编码了 callbackUrl 为 `/dashboard`，而不是保留用户原本访问的路径。

**当前代码**:
```typescript
if (!authenticated) {
    // 重定向到登录页，保留 callbackUrl
    redirect("/login?callbackUrl=/dashboard");
}
```

**问题分析**:
- 用户访问 `/dashboard/profile` 被重定向后，登录成功会跳转到 `/dashboard` 而非 `/dashboard/profile`
- 与 `proxy.ts` 中的实现不一致（`proxy.ts` 正确保留了原始路径）

**修改建议**:
使用实际访问的路径作为 callbackUrl

**修改思路**:
```typescript
export default async function DashboardLayout({ children }: DashboardLayoutProps) {
    const authenticated = await isAuthenticated();

    if (!authenticated) {
        // 获取当前完整路径
        const headers = await headers();
        const pathname = headers.get('x-pathname') || '/dashboard';
        const callbackUrl = encodeURIComponent(pathname);
        redirect(`/login?callbackUrl=${callbackUrl}`);
    }

    return <DashboardLayoutClient>{children}</DashboardLayoutClient>;
}
```
