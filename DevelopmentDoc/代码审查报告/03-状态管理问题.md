### 1. layout-store.ts 中错误地使用 `setModules` 依赖

**文件**: `src/components/features/preview/layout-preview.tsx`
**行号**: 136

**问题描述**:
虽然已经移除了 `setModules` 从 useEffect 依赖项，但注释说明了这是一个已知的无限循环问题。这表明问题的根本原因仍未解决。

**当前代码**:
```typescript
// 移除 setModules 依赖，避免无限循环
}, [session?.user?.id]);
```

**问题分析**:
- 这是权宜之计，不是真正的解决方案
- 如果 `setModules` 的实现发生变化，可能再次出现无限循环
- 代码的可维护性和可理解性降低

**修改建议**:
使用 `useCallback` 包装 `setModules`，确保引用稳定

**修改思路**:
```typescript
// 在 layout-store.ts 中，确保 setModules 是稳定的
setModules: async (modules: PageModule[]) => {
    // ... 实现
}

// 在组件中使用选择器获取稳定的引用
const setModules = useLayoutStore(state => state.setModules);

// 或使用 useRef 保存函数引用
const setModulesRef = useRef(setModules);
setModulesRef.current = setModules;
```

### 2. selector hooks 可能导致不必要的重新渲染

**文件**: `src/stores/auth-store.ts`, `src/stores/editor-store.ts`, `src/stores/layout-store.ts`
**行号**: 多处

**问题描述**:
selector hooks 没有使用浅比较，在返回对象时可能导致不必要的重新渲染。

**当前代码**:
```typescript
// src/stores/auth-store.ts:104
export const useAuthActions = () => useAuthStore((state) => ({
  setRememberMe: state.setRememberMe,
  setLoginExpiry: state.setLoginExpiry,
  clearAuth: state.clearAuth,
  isSessionValid: state.isSessionValid,
}));

// src/stores/editor-store.ts:133
export const useEditorActions = () => useEditorStore((state) => ({
  addLink: state.addLink,
  updateLink: state.updateLink,
  deleteLink: state.deleteLink,
  // ...
}));
```

**问题分析**:
- 每次调用这些 hooks 都会创建新的对象引用
- 即使状态没有变化，使用这些 hooks 的组件也会重新渲染
- 在 React Compiler 开启的情况下可能自动优化，但不应依赖编译器

**修改建议**:
使用浅比较或导出单独的 hooks

**修改思路**:
```typescript
// 方案1: 使用 zustand 的 shallow 比较
import { shallow } from 'zustand/shallow';

export const useAuthActions = () => useAuthStore(
  (state) => ({
    setRememberMe: state.setRememberMe,
    setLoginExpiry: state.setLoginExpiry,
    clearAuth: state.clearAuth,
    isSessionValid: state.isSessionValid,
  }),
  shallow
);

// 方案2: 导出单独的 hooks（更推荐）
export const useSetRememberMe = () => useAuthStore(state => state.setRememberMe);
export const useSetLoginExpiry = () => useAuthStore(state => state.setLoginExpiry);
export const useClearAuth = () => useAuthStore(state => state.clearAuth);
export const useIsSessionValid = () => useAuthStore(state => state.isSessionValid);
```

### 4. editor-store.ts 中缺少错误边界处理

**文件**: `src/stores/editor-store.ts`
**行号**: 整个文件

**问题描述**:
store 中的操作没有错误处理，如果发生错误可能导致应用崩溃。

**当前代码**:
```typescript
reorderLinks: (startIndex, endIndex) => {
    set((state) => {
      const links = [...state.links];
      const removed = links.splice(startIndex, 1)[0];

      // Guard against invalid indices
      if (!removed) {
        return state;  // 返回旧状态，但静默失败
      }
      // ...
    });
},
```

**问题分析**:
- 错误被静默吞掉，用户不知道操作失败
- 没有日志记录，难以调试

**修改建议**:
添加错误处理和日志记录

**修改思路**:
```typescript
reorderLinks: (startIndex, endIndex) => {
    set((state) => {
      try {
        const links = [...state.links];
        const removed = links.splice(startIndex, 1)[0];

        if (!removed) {
          console.warn(`reorderLinks: Invalid startIndex ${startIndex}`);
          return state;
        }

        // ... 其余逻辑

        return {
          links: reorderedLinks,
          isDirty: true,
        };
      } catch (error) {
        console.error("reorderLinks error:", error);
        // 返回旧状态，确保不会崩溃
        return state;
      }
    });
},
```

### 5. auth-store.ts 中 `isSessionValid` 的状态管理不清晰

**文件**: `src/stores/auth-store.ts`
**行号**: 67-86

**问题描述**:
`isSessionValid` 方法在会话过期时会修改 store 状态（调用 `set`），但这是一个 getter 方法，不应该有副作用。

**当前代码**:
```typescript
isSessionValid: () => {
    const state = get();

    // ... 检查逻辑

    // Session expired, clear auth
    if (state.loginExpiry && state.loginExpiry <= Date.now()) {
        set({ rememberMe: false, loginExpiry: null });  // 副作用！
    }

    return false;
}
```

**问题分析**:
- getter 方法不应有副作用
- 状态修改应该在明确的 setter 方法中进行
- 可能导致意外的状态变化

**修改建议**:
分离检查和清理逻辑

**修改思路**:
```typescript
// 检查方法 - 纯函数
isSessionValid: () => {
    const state = get();
    if (!state.rememberMe) {
        return false;
    }
    return !!(state.loginExpiry && state.loginExpiry > Date.now());
},

// 清理方法 - 明确的副作用
clearExpiredSession: () => {
    const state = get();
    if (state.loginExpiry && state.loginExpiry <= Date.now()) {
        set({ rememberMe: false, loginExpiry: null });
    }
},

// 使用方式
if (!isSessionValid()) {
    clearExpiredSession();
    signOut();
}
```
