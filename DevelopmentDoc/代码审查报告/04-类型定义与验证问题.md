## 问题列表

### 1. Project 类型在 User 和 types/index.ts 中定义不一致

**文件**: `src/types/index.ts`, `prisma/schema.prisma`
**行号**: `types/index.ts:151-159`, `schema.prisma:23`

**问题描述**:
`Project` 类型在 `types/index.ts` 中定义为接口，但在 Prisma schema 中是 `Json` 字段，类型定义与实际存储不匹配。

**当前代码**:
```typescript
// src/types/index.ts
export interface Project {
  id: string;
  name: string;
  description: string;
  url: string | null;
  imageUrl: string | null;
  tags: string[];
}

// prisma/schema.prisma
projects      Json?     // 个人项目列表
```

**问题分析**:
- Prisma 的 `Json` 类型没有编译时类型检查
- 需要手动验证 `Json` 数据是否符合 `Project` 接口
- `projectIds` 在 `ProjectsModuleData` 中引用这些项目，但使用字符串数组，容易出错

**修改建议**:
在 Server Actions 中添加 Zod 验证，确保 projects 字段的数据正确性

**修改思路**:
```typescript
// 在 validations.ts 中已有 projectSchema
// 在读取 User.projects 时应该验证
import { projectSchema } from "@/lib/validations";

const user = await prisma.user.findUnique({
  where: { id: session.user.id },
  select: { projects: true },
});

if (user?.projects) {
  const validatedProjects = z.array(projectSchema).safeParse(user.projects);
  if (!validatedProjects.success) {
    console.error("Invalid projects data:", validatedProjects.error);
    // 使用默认值或返回错误
  }
}
```

### 2. Zod schema 与 TypeScript 类型重复定义

**文件**: `src/lib/validations.ts`, `src/types/index.ts`
**行号**: 多处

**问题描述**:
多个类型同时在 Zod schema 和 TypeScript interface 中定义，违反 DRY 原则。

**当前代码**:
```typescript
// validations.ts
export const projectSchema = z.object({
  id: z.string(),
  name: z.string().min(1).max(100),
  description: z.string().max(500),
  url: z.string().url().nullable().optional(),
  imageUrl: z.string().url().nullable().optional(),
  tags: z.array(z.string().max(30)).max(10),
});

// types/index.ts
export interface Project {
  id: string;
  name: string;
  description: string;
  url: string | null;
  imageUrl: string | null;
  tags: string[];
}
```

**问题分析**:
- 两处定义需要同步维护
- 类型可能不一致（如 `url` 的 nullable 定义）
- 增加维护成本

**修改建议**:
从 Zod schema 推导 TypeScript 类型

**修改思路**:
```typescript
// validations.ts - 保持 Zod schema
export const projectSchema = z.object({
  id: z.string(),
  name: z.string().min(1).max(100),
  description: z.string().max(500),
  url: z.string().url().nullable().optional(),
  imageUrl: z.string().url().nullable().optional(),
  tags: z.array(z.string().max(30)).max(10),
});

export type Project = z.infer<typeof projectSchema>;

// types/index.ts - 重新导出
export type { Project } from '@/lib/validations';
```

### 3. ModuleData 类型与 Zod 验证不匹配

**文件**: `src/types/index.ts`, `src/lib/validations.ts`
**行号**: `types/index.ts:113-118`, `validations.ts:93-99`

**问题描述**:
`ModuleData` 是联合类型，但 `moduleDataSchema` 使用 `discriminatedUnion`，两者的字段可能不完全匹配。

**当前代码**:
```typescript
// types/index.ts
export type ModuleData =
  | LinksModuleData
  | BioModuleData
  | SkillsModuleData
  | ProjectsModuleData;

// validations.ts
export const moduleDataSchema = z.discriminatedUnion('type', [
  linksModuleDataSchema,
  bioModuleDataSchema,
  skillsModuleDataSchema,
  projectsModuleDataSchema,
]);
```

**问题分析**:
- `BioModuleData` 有可选的 `visibleFields`，但 Zod schema 中标记为 `optional()`
- 类型定义与验证定义分散在两个文件，容易不同步

**修改建议**:
确保类型定义与 Zod schema 完全一致，最好从 Zod 推导类型

**修改思路**:
```typescript
// validations.ts - 定义所有 Zod schemas
export const bioVisibleFieldsSchema = z.object({
  name: z.boolean().default(true),
  bio: z.boolean().default(true),
  avatar: z.boolean().default(true),
  phone: z.boolean().default(true),
  contact: z.boolean().default(true),
});

export const bioModuleDataSchema = z.object({
  type: z.literal('bio'),
  name: z.string().max(100),
  bio: z.string().max(500),
  avatar: z.string().url().nullable().optional(),
  visibleFields: bioVisibleFieldsSchema.optional(),
});

// 导出推断的类型
export type BioVisibleFields = z.infer<typeof bioVisibleFieldsSchema>;
export type BioModuleData = z.infer<typeof bioModuleDataSchema>;
```

### 4. LayoutItem 类型缺少 minW/maxW 的默认值

**文件**: `src/types/index.ts`
**行号**: 175-186

**问题描述**:
`LayoutItem` 中 `minW` 和 `minH` 是可选的，但在使用时没有提供默认值。

**当前代码**:
```typescript
export interface LayoutItem {
  i: string;
  x: number;
  y: number;
  w: number;
  h: number;
  minW?: number;
  minH?: number;
  maxW?: number;
  maxH?: number;
}
```

**问题分析**:
- 在 `layout-grid.tsx` 中使用 `item.minW || 1`，这种写法不处理 0 值
- 应该使用 nullish coalescing (`??`)

**修改建议**:
使用默认值或 nullish coalescing

**修改思路**:
```typescript
// 在使用时
const gridLayout = layout.map((item) => ({
  i: item.i,
  x: item.x,
  y: item.y,
  w: item.w,
  h: item.h,
  minW: item.minW ?? 1,  // 使用 ?? 而不是 ||
  minH: item.minH ?? 1,
  maxW: item.maxW,
  maxH: item.maxH,
}));
```

### 5. ThemeType 字面量类型重复定义

**文件**: `src/types/index.ts`, `src/lib/validations.ts`
**行号**: `types/index.ts:16`, `validations.ts:35`

**问题描述**:
`ThemeType` 在两个文件中重复定义。

**当前代码**:
```typescript
// src/types/index.ts:16
export type ThemeType = 'aurora' | 'cyber' | 'glass';

// src/lib/validations.ts:35
export const themeSchema = z.enum(['aurora', 'cyber', 'glass']);
```

**问题分析**:
- 重复定义
- 如果添加新主题，需要在两处修改

**修改建议**:
从 Zod schema 推导类型

**修改思路**:
```typescript
// validations.ts
export const themeSchema = z.enum(['aurora', 'cyber', 'glass']);
export type ThemeType = z.infer<typeof themeSchema>;

// types/index.ts
export type { ThemeType } from '@/lib/validations';
```

### 6. updateProfileSchema 中 projects 验证不够严格

**文件**: `src/lib/validations.ts`
**行号**: 25-32

**问题描述**:
`projects` 字段允许 `null` 值，但这会导致运行时类型问题。

**当前代码**:
```typescript
export const updateProfileSchema = z.object({
  // ...
  projects: z.array(projectSchema).max(50, 'Too many projects').optional().or(z.literal(null)),
});
```

**问题分析**:
- `.or(z.literal(null))` 的语义不清晰
- 类型推断会产生 `Project[] | null`，但 TypeScript 类型可能不匹配
- 更好的做法是使用 `.nullable()`

**修改建议**:
使用标准的 `.nullable()` 方法

**修改思路**:
```typescript
export const updateProfileSchema = z.object({
  // ...
  projects: z.array(projectSchema)
    .max(50, 'Too many projects')
    .nullable()
    .optional(),
});

// 这样会产生 Project[] | null | undefined
```
